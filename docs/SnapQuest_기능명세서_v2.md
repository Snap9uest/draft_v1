## §1 프로젝트 개요

### 한 줄 정의

**"AI가 각자에게 다른 사진 미션 빙고판을 깔아주고, 파티가 끝나면 그 판이 나만의 네컷 전리품이 된다."**

### 제품 목표

파티 중에는 사회자 없이도 스스로 돌아가는 비동기 사진 미션 게임을, 파티 후에는 캐릭터·칭호·본인 사진이 자동 조립된 개인화 네컷 티켓을 제공한다. 심사관 1인이 URL 하나만 열어도 봇 참가자와 함께 핵심 플로우를 완주할 수 있는 상태로 배포하는 것이 해커톤 기간의 목표다.

### 배경

파티 시장에서 AI는 '파티 전 노가다'(플래닝)와 '파티 후 기록'(사진 수집)에만 존재하고, 실시간으로 파티에 개입하는 '파티 중(during)' 영역은 공백이다. 오프라인 모임용 참여 도구는 사실상 Kahoot 하나뿐이며, 사진 미션 게임(GooseChase·Eventzee)과 라이브 포토월(Kululu 등), 웹 네컷(Picapica)은 각각 존재하지만 이들을 하나의 무설치 웹 플로우로 묶고 그 산출물을 개인 전리품으로 자동 조립하는 제품은 없다.

### 사용자 문제

- 호스트: 파티의 분위기 조성(사회자 역할)이 가장 비싸고 부담스러운 일인데, 대체 수단이 없다. "파티에서 제일 비싼 게 사회자다."
- 게스트: 파티 사진은 찍히기만 하고 내 손에 남지 않는다 — 요청 기반 사진 회수율은 15%에 그친다. 파티가 끝나면 남는 것이 없다.
- 기존 사진 미션 게임(공용 미션·수동 인증·소감 타이핑)은 참여 마찰이 커서 업로드 전환율을 스스로 깎는다.

### 해결 방안

1. QR 입장(설치·로그인 없음) → AI 캐릭터 프로필 → TV 로비 (파티 시작 연출)
2. AI가 참가자 프로필을 크로스한 **각자 다른 3×3 사진 미션 빙고판** — 비동기·자체구동이라 사회자 진행 없이 파티 내내 돌아감
3. AI 비전 자동 인증 + 자동 캡션(타이핑 마찰 제거) → 라이브 포토월 실시간 반영 + 사회자 리액션
4. 파티 말미 칭호 시상 → 종료 후 캐릭터+칭호+본인 사진을 캔버스 합성한 **개인화 네컷 티켓**(인스타 스토리 규격)
5. 방 링크가 그대로 공동 롤필름 앨범 + 내 티켓 아카이브 (7일 보관, 만료 3일 전 알림)

### 차별점

- **게임 플레이 데이터(캐릭터·칭호·본인 귀속 미션샷)를 1인당 인스타 규격 전리품으로 자동 조립하는 엔딩** — 이 정확한 조합은 직접 경쟁자가 없다. 단, 이는 해자가 아닌 기능이며 복제 가능함을 인정한다. 방어는 속도와 번들(파티 중 게임 + 파티 후 전리품이 한 제품)로 한다 (§4 참조).
- 무(無)얼굴인식 개인화: 사진은 찍은 사람 갤러리에 귀속 — 프라이버시·저비용 설계.
- 생성형 호출은 인당·장당 상한이 고정된 것뿐(입장 시 캐릭터·개인 판 각 1회, 사진 1장당 비전 판정 1회, 칭호·멘트 배치 1회) + 결정적 캔버스 합성(실패 없음·원가 0)의 깨끗한 단위경제 — 비전 판정을 포함해도 이벤트당 AI 원가 ₩500~2,000.
- 봇 참가자 내장 = 심사관 1인 풀 플로우 완주 장치.

### 타깃 사용자

- 1차: 20~30대 친구 모임·동아리/커뮤니티 파티의 **호스트** (지불·확산의 시작점)
- 2차: 브랜드·기업 행사 담당자 (커스텀 프레임·워크샵 모드의 지불자)

### 사용자 시나리오

동아리 개강 파티 호스트 지민은 방을 만들어 빔프로젝터에 QR을 띄운다. 게스트 15명이 폰으로 입장해 닉네임과 셀카(또는 자기소개 3줄)를 넣으면 TV 로비에 각자의 AI 캐릭터가 모이고 사회자가 멘트로 소개한다. 각자 폰에는 서로 다른 3×3 빙고판 — "처음 만난 사람과 하이파이브 샷", "○○님과 케미샷" 같은 함께 찍기 미션이 깔린다. 사진을 올리면 AI가 자동 인증하고 캡션을 달아 TV 포토월에 띄운다. 파티 말미, AI가 "K-케미장인" 같은 칭호를 시상하고 베스트샷 투표가 열린다. 종료 후 각자 4장을 골라(또는 AI 추천) 캐릭터와 칭호가 꾸며진 네컷 티켓을 받고, 방 링크는 그대로 공동 앨범이 되어 다음날 다시 열어본다.

### 핵심 지표

| 지표 | 정의 |
|---|---|
| 프로필 생성률 | 입장자 중 닉네임+캐릭터 소스(셀카/자기소개) 완료 비율 |
| 인당 미션 인증 수 | 참가자 1인당 인증 완료 미션 수 |
| 빙고 달성률 | 1줄 이상 완성한 참가자 비율 |
| 티켓 생성·다운로드율 | 종료 후 네컷 티켓을 생성·저장한 참가자 비율 |
| 초대 링크 전환(K) | 참가자 초대 링크 경유 신규 입장 수 / 참가자 수 |
| 앨범 재방문율 | 파티 다음날 이후 방 링크 재방문 비율 |
| 만료 알림 클릭률 | 만료 3일 전 알림 노출 대비 앨범 재진입 비율 |

### [F1] QR 입장 & AI 캐릭터 프로필 🔴 — MVP(1일차)

게스트가 QR/방코드/URL로 설치·로그인 없이 입장하고, 닉네임 + (셀카 1장 또는 자기소개 3줄)로 AI 캐릭터 일러스트를 받는다. 생성은 **비차단** — 기다리지 않고 다음 단계로 진행한다.

**수용 기준**
1. ✅ QR·방코드·URL 세 경로 모두에서 설치·로그인 없이 입장 폼까지 도달한다.
2. ✅ 프로필 제출 즉시 빙고판 화면으로 진행되며, 캐릭터 생성 완료를 기다리는 차단 화면이 없다.
3. ✅ 캐릭터 생성 실패 또는 타임아웃 시 프리셋 아바타가 자동 적용되고 플로우가 끊기지 않는다.
4. ✅ 생성 완료 시 TV 로비에 캐릭터가 등장하고 LLM 사회자 소개 멘트가 1회 표시된다.

**개발 준비 슬롯**

| 슬롯 | 내용 |
|---|---|
| 전제조건 | 호스트가 방을 생성해 방이 활성 상태 |
| 트리거 | QR 스캔 / 방코드 입력 / 초대 URL 클릭 |
| 동작 | 닉네임(필수) + 셀카 1장 또는 자기소개 3줄(택1) 입력 → 참가자 등록 → 캐릭터 생성 API 비동기 호출 → 완료 시 아바타 교체 |
| 결과 | 참가자 레코드 생성, 폰은 빙고판 화면으로 이동, TV 로비에 캐릭터+소개 멘트 반영 |
| 예외 | 생성 실패·타임아웃 → **프리셋 아바타 자동 폴백**(완료 시 조용히 교체) / 카메라 권한 거부 → 자기소개 3줄 경로 안내 / 재접속 → 브라우저 로컬 토큰으로 세션 복원(닉네임 재입력 없음) / 멘트 LLM 실패 → 프리셋 소개 문구 폴백 |
| 표시 | 폰: 입장 폼, "캐릭터 만드는 중" 비차단 배지 / TV: 로비 캐릭터 그리드 + 사회자 멘트 |
| 권한&접근 | 게스트 전원, 인증 없음. 데모 방은 URL만으로 진입 가능 |
| 비즈니스 규칙 | 캐릭터 생성은 인당 1회(원가 통제 — 이벤트당 AI 원가 ₩500~2,000 구조의 전제). 셀카 원본은 캐릭터 생성에만 사용하고 화면에 노출하지 않는다 |
| 데이터 | rooms JSON 내 participants: {id, nickname, avatar_url(프리셋/생성), intro, session_token, joined_at, invited_by} |

### [F2] AI 개인화 빙고판 🔴 — MVP(1일차)

AI가 참가자 프로필을 크로스해 **각자 다른 3×3 사진 미션 빙고판**을 생성한다. GooseChase의 AI 미션 생성기가 만드는 것은 전원 공용 미션 리스트지만, 본 제품은 참가자 프로필을 크로스해 참가자마다 상이한 판을 깐다 — 기능 단독으로도 커머디티가 아니다. 미션은 전부 동의 기반 '함께 찍기'("○○님과 케미샷")이며 도촬류를 금지한다. 데모 방에는 **봇 참가자**가 내장돼 심사관 1인이 URL만 열어도 풀 플로우를 체험할 수 있다.

**수용 기준**
1. ✅ 참가자마다 서로 다른 3×3 판이 생성된다 (전원 동일 판 없음).
2. ✅ 생성된 미션 전부가 동의 기반 '함께 찍기' 문구이며 도촬류·타인 무단 촬영 유도 미션이 0건이다.
3. ✅ 호스트가 미션 톤 프리셋(친목/동아리/워크샵 등)을 선택하고 개별 미션을 수정할 수 있다.
4. ✅ 데모 방에서 봇 참가자가 주기적으로 미션을 인증해 판과 포토월이 살아 움직인다.

**개발 준비 슬롯**

| 슬롯 | 내용 |
|---|---|
| 전제조건 | 참가자 프로필 1개 이상 존재, 호스트가 톤 프리셋 선택(기본값 제공) |

### [F3] 사진 인증 (AI 비전) 🔴 — MVP(1일차)

칸 선택 → 촬영/업로드 → **AI 비전 자동 인증 + 자동 한 줄 캡션**. 참가자는 캡션을 선택적으로 수정만 한다 — **필수 타이핑 없음**. 판정 실패·불확실 시 수동 인증(셀프 체크) 폴백. 하단 카메라 버튼이 상시 노출되어 자유 사진은 찍은 사람 갤러리에 자동 귀속된다(얼굴인식 없음).

**수용 기준**
1. ✅ 칸 선택→촬영/업로드→인증 완료까지 참가자의 필수 타이핑이 0회다.
2. ✅ AI 판정 실패·불확실 시 수동 인증(셀프 체크) 버튼이 노출되고, 이 경로로도 칸이 채워진다.
3. ✅ 하단 카메라 버튼으로 찍은 자유 사진이 찍은 사람 갤러리에 자동 귀속된다 (얼굴인식 미사용).
4. ✅ 자동 캡션이 사진과 함께 저장되며, 수정은 선택 사항이다.

**개발 준비 슬롯**

| 슬롯 | 내용 |

| 동작 | 클라이언트에서 canvas 리사이즈·JPEG 재인코딩 → Storage 업로드 → AI 비전 판정+캡션 생성 → 성공 시 칸 완료 처리 → 포토월 큐 등록 |

| 권한&접근 | 본인 판의 칸만 인증 가능, 자유 사진은 찍은 사람에게만 귀속 |

### [F4] 라이브 포토월 + 사회자 🔴 — MVP(1일차)

인증 사진·캡션이 현장 TV 스크린에 실시간 렌더되고 사회자 리액션 멘트가 붙는다. **호스트 숨김 버튼**으로 초상권 사고를 방지한다. 콘텐츠가 없을 때는 시드/봇 콘텐츠로 빈 화면을 막는다.

### [F7] 엔딩 네컷 티켓 🔴 — 데모 생존성(2일차 전반)

v1의 '네컷 만들기'와 '포토 티켓'을 하나로 **통합**한 기능. 종료 후 각자 빙고+자유 사진에서 4장을 선택하거나 AI 추천을 받아(부족한 칸은 내 캐릭터·칭호 카드로 채움), 캔버스 합성으로 캐릭터+칭호가 꾸며진 개인화 네컷(영수증 티켓 스타일, 인스타 스토리 규격)을 생성한다. AI 추천은 규칙 기반이다 — 인증 시각·베스트샷 투표 수 상위 4장 자동 선택, 생성형 호출 0(결정적 합성 원가 0 주장과 정합). 단체 프레임 1장은 호스트 종료 처리(F9) 시 서버가 전 참가자 캐릭터+베스트샷 투표 상위 인증샷으로 자동 합성해 공동 앨범에 게시한다. 기본 프레임 3종 무료. **추가 프레임 해금은 2경로만**: ① 빙고 1줄 달성 ② 내 초대 링크로 신규 참가자 1명 입장. SNS 공유 해금(검증 불가)과 결제 해금(모의결제 리스크)은 넣지 않는다 — 유료 커스텀 프레임은 §4 수익 모델 서술로만 다룬다.

**수용 기준**
1. ✅ 4장 직접 선택과 AI 추천(규칙 기반: 인증 시각·베스트샷 투표 수 상위 4장 자동 선택) 두 경로 모두 동작하며, 사진이 4장 미만이어도 캐릭터·칭호 카드 자동 채움으로 티켓이 반드시 생성된다.
2. ✅ 합성 결과가 캐릭터+칭호가 포함된 인스타 스토리 규격 이미지이며, 한글 텍스트가 깨지지 않는다.
3. ✅ 기본 프레임 3종은 즉시 사용 가능하고, 잠금 프레임은 '빙고 1줄' 또는 '초대 입장 1명' 충족 시에만 서버 데이터 검증으로 해금된다.
4. ✅ 캔버스 합성 실패 시 플레이스홀더 티켓으로 폴백되어 엔딩 플로우가 끊기지 않는다.
5. ✅ 호스트 종료 처리 시 서버가 전 참가자 캐릭터+베스트샷 투표 상위 인증샷으로 단체 프레임 1장을 자동(결정적 캔버스 합성, 생성형 호출 0) 생성해 공동 앨범(F8)에 게시한다 — 참가자 조작 불필요.

**개발 준비 슬롯**

| 슬롯 | 내용 |
|---|---|
| 전제조건 | 호스트가 파티 종료 처리(F9) → 엔딩 콘텐츠 오픈 상태 |

### [F8] 공동 롤필름 앨범 & 보관함 🔴 — 데모 생존성(2일차 전반)

방 링크가 그대로 공동 앨범 + 내 티켓 아카이브가 된다(재방문만으로 접근, 로그인 없음). 저장은 이미지 꾹 눌러 저장+공유 시트(iOS 다운로드 버튼 회피). **무료 7일 보관, 만료 3일 전 알림 = 리텐션 트리거**. 영구 보관·원본 화질은 유료 티어로 §4에서만 서술한다. 앨범은 사진 공유 서비스가 아니라 게임 산출물(티켓·칭호·캐릭터·인증샷)의 전리품 보관함이다.

**수용 기준**
1. ✅ 파티 종료 후 방 링크 재방문만으로 공동 앨범과 내 티켓 아카이브에 접근된다 (로그인·앱 설치 없음).
2. ✅ 이미지 꾹 눌러 저장과 공유 시트가 iOS 사파리에서 동작한다.
3. ✅ 앨범에 "무료 보관 7일" D-day 카운터가 상시 표시되고, 만료 3일 전(D-3)부터 앨범 상단 배너가 노출된다 — 배너+D-day 카운터가 1차 수단이자 데모 범위의 전부다. 브라우저 푸시 알림은 iOS 사파리에서 홈 화면 추가(PWA 설치) 없이는 동작하지 않으므로 데모 범위에서 제외하고 정식 출시 범위로 둔다. 검증은 보관 시계를 분 단위로 단축한 데모 방(D-7 → 분 단위 시뮬레이션)에서 임계값 도달 시 배너가 노출되는 것으로 확인한다 — 1.5일 데모에서 실제 3일 경과를 기다리지 않는다.
4. ✅ 티켓 저장·공유 후 앨범 화면으로 귀결된다 — 플로우에 dead-end가 없다.

**개발 준비 슬롯**

| 슬롯 | 내용 |
|---|---|
| 전제조건 | 방 존재(종료 여부 무관 — 종료 후에도 링크 유지), 세션 토큰으로 '내 것' 식별 |
| 트리거 | 방 링크 재방문, 티켓 생성 완료 후 자동 이동 |
| 동작 | 공동 롤필름 뷰(전원 인증샷·단체 프레임, 숨김 처리분 제외) + 내 아카이브 탭(내 티켓·캐릭터·칭호) 렌더 → 꾹 눌러 저장/공유 시트 안내 |
| 결과 | 파티 다음날 재방문 동선 확보, 저장·공유 자산 전달 완료 |
| 예외 | 세션 토큰 유실(다른 브라우저) → 공동 앨범은 열람 가능, 내 아카이브는 닉네임 재확인으로 복원 / 만료 도래 → 만료 안내 페이지(데모 범위: 안내 문구까지 — 유료 연장은 §4 서술로만) / 재방문이 없으면 배너는 트리거로 성립하지 않는 순환 → **티켓 이미지·저장 화면에 보관 만료 D-day를 각인**(F7 합성 오버레이)해 폰 사진첩·공유본에서도 만료가 보이는 대체 도달 장치 확보 / 브라우저 푸시는 iOS 사파리에서 홈 화면 추가 없이는 불가 → 데모 제외, 정식 출시 범위 / 숨김 처리 사진 → 앨범에서도 비노출 |

| 권한&접근 | 공동 앨범은 방 링크 보유자, 내 아카이브는 본인 세션. 로그인·계정 없음 |
| 비즈니스 규칙 | 무료 7일 보관이 기본. 만료 3일 전 배너 + 티켓 각인 D-day가 리텐션 트리거로 설계(핵심 지표: 만료 알림 클릭률·앨범 재방문율). 푸시 알림은 정식 출시 범위. 영구 보관·원본 화질은 유료 티어 — 기능이 아닌 §4 수익 모델로만 |
| 데이터 | rooms: {expires_at}, album_items: {photo/ticket 참조, hidden}, 알림 노출 로그 |

### [F9] 호스트 진행 도구 🔴 코어 — MVP(1일차) / 🟢 대시보드 — P2(여력)

방 생성 → QR/방코드 표시, AI 미션 프리셋 생성+수정, 현장 리워드 토글(기본 꺼짐), 네컷 타임 트리거, 콘텐츠 숨김, 파티 종료 처리(→엔딩 콘텐츠 오픈). **참가·미션 통계 대시보드는 🟢 P2로 강등** — 데모 범위 외.

**수용 기준**
1. ✅ 방 생성부터 TV 뷰(`?role=tv`)에 QR/방코드 표시까지 클릭 3회 이내로 완료된다.
2. ✅ 미션 톤 프리셋 선택·수정, 콘텐츠 숨김, 종료 처리가 호스트 폰 컨트롤 뷰에서 동작하며, 조작 버튼은 TV 표시 전용 뷰에 노출되지 않는다.
3. ✅ 현장 리워드 토글은 기본 꺼짐이며, 끈 상태에서는 게스트 화면 어디에도 리워드 문구가 노출되지 않는다.
4. ✅ "시상 시작" 트리거 시 시상 플로우(F6: 칭호 발표·베스트샷 투표)가 TV와 게스트 폰에 열린다 — 로비→진행→시상→엔딩의 파티 생애주기 전환이 호스트 버튼으로 제어됨을 검증한다.
5. ✅ 종료 처리 시 게스트 전원에게 엔딩 콘텐츠(칭호 확인·티켓 생성)가 오픈되고 단체 프레임 자동 합성(F7)이 실행된다.

**개발 준비 슬롯**

| 슬롯 | 내용 |
|---|---|
| 전제조건 | 없음 (호스트도 로그인 없음 — 방 생성 시 발급되는 호스트 토큰이 권한의 전부) |
| 트리거 | 랜딩의 "방 만들기", 이후 진행 도구의 각 버튼 |
| 동작 | 방 생성(rooms 레코드+JSON 초기화) → TV 뷰(`?role=tv`)에 QR/방코드 표시 → 톤 프리셋 선택 → [파티 중, 폰 컨트롤 뷰] 네컷 타임 트리거(F5)·콘텐츠 숨김(F4)·시상 시작(F6) → 종료 처리(엔딩 오픈, F7·F8 활성 + 단체 프레임 자동 합성) |

| 예외 | 호스트 이탈·새로고침 → 호스트 토큰으로 재진입 시 현재 상태 복원 / 종료 미처리로 방치 → 보관 만료 시점에 자동 종료 처리 폴백 / 리워드 토글 ON인데 미지급 → 시스템은 안내만 표시(지급은 호스트 오프라인 재량 — 운영 부담을 제품에 지지 않음) |
| 표시 | 호스트(폰 컨트롤 뷰 — 들고 돌아다니며 조작): 진행 버튼 패널(콘텐츠 숨김·시상 시작·네컷 타임·종료), 톤 프리셋·리워드 토글, 종료 확인 다이얼로그 — 조작 버튼은 빔에 송출되지 않음 / TV(`?role=tv` 표시 전용): QR/방코드 대기 화면과 로비→포토월→시상→엔딩 연출 / (P2 🟢) 참가·미션 통계 대시보드 |

## §3 GTM 전략 [G1]

### 3.1 타깃 고객

- **1차: 20~30대 친구 모임·동아리/커뮤니티 파티의 호스트.** 사회자 역할의 부담("파티에서 제일 비싼 게 사회자다")을 지는 당사자이자, 방 생성이라는 첫 행동의 주체. 게스트는 QR로 유입되므로 획득 대상은 언제나 호스트 1명이다.
- **2차: 브랜드·기업 행사 담당자.** 커스텀 프레임과 워크샵 모드의 지불자(§4). 1차 시장에서 제품을 게스트로 경험한 직장인이 회사 행사로 가져가는 경로를 상정한다 — Slido가 실증한 웨지 경로다.

### 3.2 최초 유입 채널

- **대학 축제·동아리 OT 시즌 공략(3월·9월).** 파티 밀도가 가장 높고 호스트(집행부)가 명확한 시기·집단. 무설치·무료라는 조건이 집행부의 도입 장벽을 없앤다.
- **파티룸 대여 업체 제휴.** 파티룸에는 TV/빔이 이미 있고 — 본 제품의 TV 뷰 요구사항과 정확히 맞물린다 — 대여 업체는 "게임·포토월이 세팅된 파티룸"이라는 차별화를 얻는다. 룸 내 QR 스탠드 비치만으로 유입이 시작된다.

### 3.3 파티형 확산 구조 (메커니즘)

확산은 형용사가 아니라 제품 구조다:

1. **파티 1건 = 게스트 전원 강제 경험.** 빙고판·포토월·티켓 모두 QR 입장 없이는 참여 자체가 불가능하므로, 파티 1건이 곧 게스트 수만큼의 제품 데모다.
2. **게스트→차기 호스트 전환 루프.** 게스트 전원의 손에 남는 네컷 티켓과 방 링크(공동 앨범)가 다음 모임에서 "이거 쓰자"의 근거가 된다. 파티 1건의 게스트 30명 중 2명이 다음 달 호스트가 되면 K=2 — Partiful·Guestpix가 실증한 게스트→호스트 전환 루프를 제품 코어에 박았다.
3. **초대 링크 프레임 해금(F7)이 K-팩터에 직접 기여.** 파티 중에도 참가자가 자기 초대 링크로 신규 1명을 입장시키면 프레임이 해금된다. 해금 조건이 서버 데이터(invited_by)로 검증되므로 확산 지표(초대 링크 전환 K)가 제품 안에서 그대로 측정된다.

### 3.4 리텐션 트리거

- **만료 3일 전 알림(F8):** 무료 7일 보관의 만료 임박 알림이 앨범 재방문을 만든다. 핵심 지표 '만료 알림 클릭률'로 직접 측정.
- **다음날 앨범 재방문:** 방 링크 = 공동 앨범이므로 "어제 사진 보자"가 자연 재방문 동선이다. 티켓 저장·공유 플로우가 전부 앨범으로 귀결되도록 설계(dead-end 금지)한 이유다.
- **칭호 컬렉션:** 칭호는 참가자 귀속 자산으로 남아 파티를 거듭할수록 쌓인다 — 다음 파티 참여의 수집 동기.

## §4 비즈니스 모델 [G2]

### 4.1 수익 모델과 지불 의사

무료 티어(기본 프레임 3종·7일 보관)는 수익 모델이 아니라 **확산 장치**다. 지불자는 첫날부터 명확하다:

1. **웨딩·브랜드 커스텀 프레임 — 이벤트당 과금.** 웨딩 포토 시장은 이벤트당 $25~90 일시불 지불이 이미 검증된 카테고리다(Guestpix $49 일시불, POV $34.99/100명·$89.99/250명, 시장 표준가 $19~99). SnapQuest는 같은 '인생 이벤트 1회성 결제' 지점에 커스텀 프레임+단체 프레임을 판다. 참고로 AI 포토부스 렌탈가($200~500) 인용은 폐기했다 — 그 지불의사는 장비·인력·인쇄물에 대한 것이다.
2. **B2B 워크샵 모드 — 세션당 ₩200,000 (가설).** 같은 제품이 무료 파티 모드(확산)와 워크샵 모드(B2B 과금)를 관통하는 Slido식 웨지. Slido는 시드 $36K로 ARR $12.5M을 만들어 Cisco에 인수됐고, Kahoot은 참가자 무료·호스트 과금 모델로 $1.72B에 인수되며 이 카테고리의 지불의사와 엑싯 상한을 실증했다. 세션당 ₩200,000은 아직 가설이며, 실증된 것은 카테고리의 지불의사다.
3. **영구 보관·원본 화질 티어.** 보관 기간·화질 티어 과금은 사진 서비스에서 검증된 패턴이다. 무료 7일 만료가 전환 트리거를 겸한다.

반면교사: Partiful은 $27.3M 조달·MAU 50만(+400% YoY)에도 유의미한 매출이 없다 — "무료로 모으고 나중에 수익화"가 아니라, 이벤트당 결제하는 지불자를 첫날부터 명시하는 이유다.

### 4.2 단위 경제성

- **이벤트 1건당 AI 원가 ₩500~2,000.** 생성형 호출이 참가자 캐릭터 입장 시 1회 + 미션·칭호 배치 호출뿐이고, 네컷 티켓은 결정적 캔버스 합성이라 원가 0이다.
- 검증된 객단가 ₩30,000~300,000 대비 **매출총이익률 95%+** — 첫 결제부터 흑자 구조.
- 운영 확장성: 게임 상태가 DB JSON 1개(Supabase Realtime)로 관리되고 실물 운영 요소(리워드)는 호스트 선택 토글로만 존재하므로, 방 수 증가에 따른 한계 운영 비용이 서버·API 비용뿐이다.

### 4.3 시장 규모와 성장 논리 (바텀업)

- 초기 쐐기 시장(웨딩·인생 이벤트): **한국 연간 결혼 약 20만 건 × 침투율 5% × ₩39,000 = 초기 SOM ₩3.9억.** 하객 전원이 QR을 스캔하며 제품을 경험하므로 판매 1건이 곧 수백 명 단위의 데모다(게스트→차기 호스트 전환).
- 인접 확장(돌잔치·브랜드 행사·B2B 워크샵)으로 **₩100억** 규모까지 성장 논리를 잇는다. 탑다운 수십조 TAM은 인용하지 않는다 — 그 숫자는 대관비와 케이터링이지 우리 매출이 아니다.

### 4.4 방어 가능성·차별점

- 부품별 경쟁자는 전부 존재한다: 사진 미션 게임은 GooseChase(AI 미션 생성기 상용 탑재)·Eventzee(파티팩 $49.99), 라이브 포토월은 Kululu 등 다수, 웹 네컷은 Picapica. 이를 인정한다.
- 살아남는 차별화는 조합이다: **"게임 플레이 데이터(캐릭터·칭호·본인 귀속 미션샷) × 네컷 자동 조립 엔딩"의 정확한 조합은 직접 경쟁자가 없다.** 각자 다른 AI 개인화 빙고판(공용 프리셋 판과의 차별)과 무얼굴인식 귀속 설계가 조합의 재료다.
- 단, **이 조합은 해자가 아니라 기능이다.** 복제 가능함을 인정하고, 방어는 ① 속도(카테고리에 아직 승자가 없는 '파티 중' 공백 선점) ② 번들(파티 중 게임 + 파티 후 전리품이 한 제품 — 부품 복제로는 재현되지 않는 단일 플로우) ③ 칭호 컬렉션 데이터 누적으로 서술한다.

## §5 데모 시나리오 (심사관 체험 순서)

심사관 1인이 URL 하나로 핵심 플로우를 완주하도록 설계했다. 데모 방에는 봇 참가자가 활동 중이며, 랜딩에 `?role=tv`(TV 뷰)·`?role=host`(호스트 폰 컨트롤 뷰)·`?role=player`(게스트 뷰) 링크가 나란히 있어 탭 3개로 전체 구조를 파악할 수 있다.

1. **랜딩 진입** — 첫 뷰포트에 무엇·왜·어떻게 3줄 피치와 "데모 방 입장" 버튼, tv/host/player 링크 3개.
2. **[탭 A] `?role=tv`** — TV 뷰(표시 전용): QR/방코드, 봇 캐릭터들이 모인 로비와 사회자 멘트가 이미 돌아가는 중(빈 화면 없음).
3. **[탭 B] `?role=player`** — 설치·로그인 없이 입장 폼. 닉네임 + 자기소개 3줄 입력(셀카 없이도 진행됨을 확인).
4. **비차단 확인** — 캐릭터 생성을 기다리지 않고 즉시 개인 빙고판 도착. 잠시 후 탭 A 로비에 내 캐릭터 등장 + 소개 멘트.
5. **개인화 확인** — 내 3×3 판의 미션이 봇 참가자 이름을 크로스한 '함께 찍기' 미션임을 확인(봇의 판과 다름).
6. **사진 인증** — 칸 선택 → 이미지 업로드(시드 이미지 안내 제공) → AI 자동 인증 + 자동 캡션, 타이핑 0회. 탭 A 포토월에 실시간 등장 + 사회자 리액션.
7. **호스트 조작** — [탭 C] `?role=host` 폰 컨트롤 뷰에서 사진 1장 숨김(탭 A TV에서 즉시 제거 확인) → "시상 시작": 탭 A에 칭호 발표 + 베스트샷 투표(봇 투표 진행).
8. **종료·티켓** — 탭 C에서 종료 처리 → 탭 B에 엔딩 오픈: 4장 선택 또는 AI 추천(부족 칸은 캐릭터·칭호 카드 채움) → 캐릭터+칭호가 얹힌 영수증 스타일 네컷 티켓 합성.
9. **해금 확인** — 잠금 프레임에 해금 조건 2경로(빙고 1줄/초대 입장) 안내가 표시됨을 확인 — 결제·SNS 공유 요구 없음.
10. **앨범 귀결** — 티켓 저장 화면에서 앨범으로 이동: 공동 롤필름 + 내 아카이브 + 보관 D-day와 만료 알림 배너. 방 링크 재방문으로 동일 화면 재진입 확인 (dead-end 없음).

소요 약 3분. 제출 직전 시크릿 창에서 콘솔 에러 0건·404 없음을 최종 점검한다.
